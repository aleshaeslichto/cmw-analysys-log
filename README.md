# comindware-log-analysis

Скилл для opencode: анализ логов платформы Comindware при инцидентах. Работает по схеме **опрос → анализ → отчёт → обучение**:

1. **Опрос** — выясняет тип проблемы (производительность, ошибки и исключения, падение сервисов, интеграции, аутентификация и лицензии, база данных), путь к директории с логами и период анализа.
2. **Анализ** — изучает структуру логов, выбирает релевантные файлы под категорию, собирает фрагменты и восстанавливает хронологию инцидента.
3. **Отчёт** — подробный отчёт с фрагментами логов, хронологией и рекомендациями по решению.
4. **Обучение** — по запросу «зафиксируй действия» скилл сохраняет усвоенные уроки в `LEARNINGS.md` и применяет их в следующих разборах.

## Структура

```
comindware-log-analysis/
├── SKILL.md          # описание скилла (процесс, категории, шаги анализа)
└── LEARNINGS.md      # накопленные уроки (самообучение скилла)
```

## Подключение вручную

Скилл хранится вне стандартных каталогов opencode, поэтому его нужно зарегистрировать через `skills.paths` в конфиге.

### Вариант 1. Глобально (доступно в любом проекте)

В файл глобального конфига добавь `skills.paths`:

- Linux/macOS: `~/.config/opencode/opencode.json` (или `.jsonc`)
- Windows: `%USERPROFILE%\.config\opencode\opencode.json`

```json
{
  "$schema": "https://opencode.ai/config.json",
  "skills": {
    "paths": ["/путь/до/comindware-log-analysis"]
  }
}
```

Пример для этого репозитория, если он склонирован в `~/gh-repos`:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "skills": {
    "paths": ["~/gh-repos/comindware-log-analysis"]
  }
}
```

### Вариант 2. В конкретном проекте

Положи скилл в каталог проекта:

```
.opencode/skills/comindware-log-analysis/
└── SKILL.md
```

(скопируй папку `comindware-log-analysis` целиком) — тогда конфиг менять не нужно, скилл подхватится автоматически.

### Вариант 3. Через симлинк (обновления в репо подхватываются сразу)

```
ln -s /путь/до/comindware-log-analysis ~/.config/opencode/skills/comindware-log-analysis
```

## Команда /skill

Чтобы вызывать скилл вручную, создай файл команды `~/.config/opencode/commands/skill.md` (для глобального доступа) или `.opencode/commands/skill.md` (для проекта):

```markdown
---
description: Анализ логов платформы Comindware (опрос → анализ → отчёт)
---

Загрузи скилл comindware-log-analysis с помощью инструмента skill и выполни его воркфлоу полностью: сначала опрос пользователя о типе проблемы, затем анализ логов из указанной директории, затем подробный отчёт с фрагментами логов и рекомендациями.

$ARGUMENTS
```

## Использование

1. **Перезапусти opencode** — конфиг читается только при старте.
2. Скилл автоматически подхватывается при упоминании анализа логов Comindware, либо запусти вручную:
   - `/skill` — начнёт воркфлоу с опроса;
   - `/skill путь/к/логам` — с уже указанной директорией логов.
3. Во время анализа, если нашёл что-то поучительное, скажи «зафиксируй действия» — скилл сохранит урок в `LEARNINGS.md` и будет применять его в следующий раз. Правки самого `SKILL.md` скилл только предлагает и ждёт твоего одобрения.

## Проверка подключения

После перезапуска в `<available_skills>` агента должен появиться `comindware-log-analysis`. Если скилл не виден, проверь:

1. Файл называется `SKILL.md` (заглавными буквами) и лежит в папке `comindware-log-analysis/`.
2. Имя в frontmatter (`name: comindware-log-analysis`) совпадает с именем папки.
3. Путь в `skills.paths` указывает на папку, содержащую `SKILL.md` (сканирование рекурсивное).
4. Имя скилла уникально — нет конфликта с другими скиллами в системе.
5. Права на чтение каталога скилла доступны процессу opencode.
